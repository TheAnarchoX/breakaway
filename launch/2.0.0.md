## The story

**In one line:** breakaway runs the infrastructure too, and you still decide.

**The headline:** Agents propose it. You approve it.

It rhymes with the board's own line, "Agents claim the work. You merge it.", on purpose: Architect is the same deal, moved from code to what the code runs on. That's the whole story, and every piece tells it the same way:

1. **The board sees what runs.** Connect a provider (Cloudflare first) with a read-only token, and the Infrastructure view shows each repository's environments: what runs there, what it uses, its health, and what it costs.
2. **Agents propose by pull request.** What should exist is a file in the repository. An agent changes it in a pull request, and the pull request shows the plan as a check: what changes, what it costs, what else it touches, and whether it can be undone.
3. **You approve. The board applies.** A plan that waits pushes to your phone. You press Approve; the board applies it, checks health, and rolls back by itself if the check fails. No agent can press Approve, and the board holds no write credentials.
4. **Bounds you set once.** An envelope lets the board scale and restart inside limits you approved, and tells you after. Anything outside them waits for you.
5. **When something breaks, it's a task.** A signal that crosses a rule opens an incident on the board, in the repository that owns what broke. A production incident pushes.

The board's own install is observe only: Architect watches it and never changes it. Say it in the long pieces; it's the proof that the rules hold.

## What's new, in plain words

The list the thread's first card and the release notes start from. `DOC-41` cuts any line that didn't ship.

- **The Infrastructure view**: your repositories' environments, with health, cost, drift, and the plan waiting.
- **Plans you approve**, from your phone, before anything changes.
- **Plans in pull requests**: change what should exist in a file, and the pull request shows the plan as a check.
- **Envelopes**: bounds you approve once, for scaling and restarts.
- **Incidents**: a signal that crosses a rule opens a task, and a production incident pushes.
- **Freeze** an environment, and no plan runs there until you unfreeze it.
- **Cost** by environment, repository, and task, with budgets, marked as estimates.
- **`npx breakaway infra`** in the CLI, and the same reads on the MCP server.

## The claims it leans on

Every piece says only these. Each is in the brand guide's [Claims that must stay true](../brand/README.md#claims-that-must-stay-true), or is one of Architect's claims the guide lists for "once it ships".

| Claim | Where it comes from | Must stay true because |
| --- | --- | --- |
| **You decide.** Nothing merges or deploys on an agent's word. | The guide's list | Architect is that rule moved to infrastructure. If an agent could apply, the story is false. |
| **Agents propose infrastructure changes and never apply them.** | Architect's claims, for once it ships | Agents hold no write credentials; Approve is cookie-only. |
| **Nothing changes without your approval, or inside bounds you approved once (an envelope).** | Architect's claims | The default policy asks for every plan, in every environment. |
| **The board only watches its own install.** | Architect's claims | The board's environment is always observe only. |
| **It runs on Cloudflare**, and Cloudflare is the first provider. | The guide's list; IDEA-19 | Say "Cloudflare first", never "any cloud". |
| **An install keeps its data.** Signals and the inventory stay in your install, redacted. | `AGENTS.md` | No telemetry; the read token only goes to its provider. |
| **Free, and the source is public.** | The guide's list | Architect is in the same licence: no paid tier, no hosted version. |
| **Pull requests close tasks**, and infrastructure changes are pull requests too. | The guide's list | The plan check is on an ordinary pull request. |

Architect's three claims move into the guide's list when 2.0.0 ships: `ID-7` does it in its own pull request, before `DOC-41` reads the launch copy against the guide.

**Never say**, in any piece: that it manages "your whole cloud" or "any cloud" (it manages what the board's repositories run on, on Cloudflare first); autopilot, self-healing, hands-off, or anything that reads as the board acting on its own (envelopes are bounds you approved); AIOps, DevOps, IaC, control plane, or the other ops jargon the guide leaves out; uptime, speed, or cost numbers nobody measured; or anything about what someone ran or saved with it.

### 6. The film: a hero film and a 16 s cut (storyboard `LCH-37`, made by `LCH-38`)

The owner asked for a video with real motion that shows the power ([`LCH-36`](#the-owners-choices-lch-36)): one setup growing from a small app to a scaled one, the whole loop run by agents, and you deciding at every step that changes something. So there are two cuts of one storyboard, replacing the single 16-second plan:

- **The hero film**, about 84 s, for the site's Architect page and the Show HN, which links it there. Two renders: `media/2-0-0-film.mp4` (1920 by 1080) and `media/2-0-0-film-square.mp4` (1080 by 1080, for Reddit). The same shots; the wide one sets the line on the left third and the board on the right two thirds, the square one the line above the board.
- **The 16 s cut**, `media/2-0-0.mp4` (1080 by 1080), for 9a on X, pinned for launch week. It replaces the one `LCH-32` made.

Both are 30 fps, no sound, made by `video.mjs` from scenes whose `render(t)` draws each frame, over the real views captured from the seeded launch board, never a still that pans.

**The message:** breakaway closes the loop of building software on one board. An idea becomes tasks, a task a pull request, the merge a deploy, a change to what runs a plan, the plan an approval and an apply, what runs a signal, a signal an incident, and the incident a task again. Agents do the work at every step; you merge, promote, and approve.

**The closing line** is "From idea to incident, on one board." then "You decide." The owner wanted to say it's the first agentic tool to close the loop of building software; a "first" can't be proven and is the line people would argue with, so the owner chose wording with nothing to dispute (their answer, relayed on `LCH-37` on 7 Oct 2026). No line in either cut says first, only, fastest, or any number of what someone shipped.

**How it moves.** Motion follows the guide: fast out on `--ease`, no bounce, things arrive from the left and leave to the right, 280 ms for anything that enters. The power is shown by things arriving and growing: nodes join the console's map one by one, the environment's stream flows as entries land at its top, a chase's graph fills as agents claim, and the roadmap timeline's bars slide as features move. One red thing on screen at a time: the red number of the task being worked, Approve as it's pressed, or the red word of a line. Nothing flashes more than three times a second. Each shot holds still long enough to read its line (at least 1.5 s after the last thing arrives).

**Reduced motion.** The site plays the film only on a press, never on its own, and with reduced motion set it shows the poster with a link to the film instead. The posters are still frames that read on their own.
