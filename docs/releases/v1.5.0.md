breakaway 1.5.0 brings the board into Claude Code. Every board is now an MCP server at `/mcp`, and breakaway's plugin for Claude Code puts the `tasks` skill, three commands, the session hooks, and that MCP server in one install. Claude's apps sign in to `/mcp` with a connection you approve on the board.

### The MCP server

- **Every board is an MCP server** at `/mcp` on its own address, on as soon as your board updates. Claude Code, or any client that speaks MCP over HTTP, lists, claims, and comments on tasks with tools instead of the CLI, with the same token and the same rules: one claim per task, and nothing merges or deploys on an agent's word.
- **Its tools** read the board (tasks, specs, features, a pull request's checks) and do what an agent does from the CLI: claim and release, comment, add and change tasks, ping you, review a pull request, post on the peloton, and read your messages. There's no tool to mark a task done, force a claim, start an agent, merge, or release.
- **Resources and prompts**: a task, a spec, and the repository's agent prompt as resources, and `work_on_task` and `shape_idea` as prompts, so a client that never read the `tasks` skill follows the same loop.
- `npx breakaway mcp` prints the `claude mcp add` line and the `.mcp.json` entry for the checkout you're in, with `$BREAKAWAY_TOKEN` where the token goes, and `mcp --check` says whether `/mcp` answers.

### Claude's apps

- **Add your board as a custom connector** in claude.ai or Claude Desktop: your board's address followed by `/mcp`. The board opens its sign-in page, where you name the connection, pick its repository and the agent name it claims as, and press **Approve** or **Deny**.
- Each connection has its own token, never the board's: it works only on `/mcp`, for that one repository and agent name.
- **Connections** lists them under **Claude's apps**, with **Revoke**, which stops a connection at once.

### The Claude Code plugin

- **breakaway's plugin for Claude Code** carries the `tasks` skill, `/breakaway:claim <ID>`, `/breakaway:next`, `/breakaway:hand-over`, the session hooks that post a task's output live and wake a session when you message it, and the board's MCP server, connected for you.
- **Install it for yourself** from breakaway's marketplace: `/plugin marketplace add TheAnarchoX/breakaway`, then `/plugin install breakaway@breakaway`. Claude Code asks for your board's address, its token (kept in your system keychain), and, if you like, an agent name. A machine you already set up keeps its settings: the plugin's come last.
- **Install it for a repository**: `npx breakaway repos init <slug>` turns the plugin on in the repository's `.claude/settings.json`, so every Claude Code session there gets it, the board's cloud agents included. `--update` moves a repository from the copied skill and hooks to the plugin in one pull request, and `--copies` keeps the copies.
- The marketplace follows the `plugin` branch, which each stable release moves, so you get released versions, never work in progress. 1.5.0 is the first release on it.

### On the board

- **Pull into next** on the roadmap stages the next release's work that's still in later, with what it waits for, in next.
- A check that CI cancelled because a newer run replaced it no longer shows a pull request as failing.
- Dictation on Android no longer repeats words.

### Updating

Nothing by hand: update and deploy as usual, and `/mcp` and the sign-in for Claude's apps are on. Update your board before you install the plugin: the plugin names the repository the way only 1.5.0's `/mcp` understands.

- To move a repository the board already runs to the plugin, run `npx breakaway repos init <slug> --update` in its checkout, and merge the pull request it opens.
- The plugin's first `npx --yes breakaway@1` download can take longer than Claude Code waits for the MCP server. If `/mcp` shows `breakaway` failed the first time, reconnect it there.
