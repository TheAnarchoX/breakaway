breakaway 2.0.0 runs the infrastructure too, and you still decide. With **Architect**, agents propose changes to what your repositories run on by pull request, the plan waits for you on the board, and your repository's own apply workflow applies it. And from 2.0.0, breakaway is free for personal and noncommercial use, under the PolyForm Noncommercial License 1.0.0.

### Architect

- **Connect a provider** on **Connections**: Cloudflare, with a read-only token. A checklist on each repository's card links to Cloudflare's token page with the permissions filled in, and shows, per environment, whether its GitHub environment is ready: it exists, only the default branch may deploy, and it holds the write token. The write token lives there, never on the board. With no provider connected, Architect stays off and makes no call.
- **Infrastructure** is a new view (`g` then `n`): each repository's environments, their health, cost, and freeze, and the platform's alerts. A repository on the deploy flow gets staging and production by itself, with its deploys, Promote, and Roll back recorded on them.
- **Each environment is a console**: a map of what runs and how it's bound, a live stream of its signals, its plans, incidents, drift, what nobody owns, and recent deploys. What the desired state declares stays on the map until the inventory sees it.
- **Desired state lives in the repository**, in `.github/breakaway-infra/<environment>.json`. Nobody has to write the first one: **Describe it as code** drafts it from what runs, and `npx breakaway infra adopt` writes it into a checkout.
- **Plan from the board.** On the console, change a setting, add a resource from a template, or remove one, and watch the plan form as you edit. **Propose the change**, and the board opens its pull request, with the apply workflow in it when the repository doesn't have one yet. **Approve** merges it and applies it. You can also build an environment from nothing, or have an agent set one up in a short wizard.
- **Every plan says** what changes, what it costs, what else it touches, and whether it can be undone, and it shows as a check on its pull request. The **policy** decides which plans wait for you, per repository and per environment, and you change it in place on its own page; loosening it is never one press.
- **Approve and Reject are yours**, on the board, like Merge. The repository's apply workflow applies an approved plan under the environment's lock, checks its health, and rolls back if it fails. A run that failed before applying anything can be started again, and an applied plan looks at the environment again at once.
- **Envelopes** are bounds you approve once on an environment, like "2 to 10 instances" or "3 restarts a day". Inside one, the board scales and restarts without asking you again. They start empty, so until you set one, every scale and restart waits for you.
- **Signals and incidents.** Health, the platform's alerts, and cost are signals. One that crosses a rule opens an incident, a task tagged `+incident` in the repository that owns what broke, with its steps: diagnose, propose, approve, apply, verify. An agent diagnoses it only when you start one, or from a runbook you turned on. Routines can start on signals, on infrastructure events, and on new issues.
- **Drift** shows what runs that no longer matches the desired state. **Mark as break-glass** records a change you made by hand and adds a task to put it in code; the board never undoes it.
- **Cost** is an estimate per resource, added up by environment, repository, and task, with a budget per environment and a signal near it and over it. Pick your currency in Settings.
- **Short-lived environments**: one per task when a repository asks for it, removed when the task closes.
- **Freeze** stops every plan on an environment. Freezing a pipeline's production is the deploy pause too: the board sets `DEPLOYS_PAUSED`, and Roll back still works.
- **Agents work infrastructure** the way they work code, and neither they nor the board hold write credentials: `npx breakaway infra` and the MCP server read environments, plans, signals, and incidents; `infra check` and `infra add` write a change for a pull request. Agents never apply or approve.
- **The board's own install is observe only**: Architect watches it and never changes it.

### On the board

- **The roadmap is a timeline**: each feature from its first work to when the board's pace says it's likely done. Give a feature a planned start and end, drag its bar, and see whether the pace agrees. Agents can plan the roadmap too, and every change they make shows in Activity with an undo.
- **Feature pages open on an overview**, with the full task list a step away. The graph folds done work and shows the path to the last task.
- **Code in diffs is highlighted**, and Markdown and text files preview as a rendered diff.
- **Build a pre-release** from a repository's release flow on the board, and see when `main` is ahead of the latest one.
- The board spends less of GitHub's rate limits, shows what's left per repository on Connections, and paces a busy repository's sync by the budget left.
- Pings no longer have a count per task, and a proposal no longer has a count of changes, only its size.
- Settings and Connections are laid out across the width, the peloton's posts can be resized, and scrollbars follow the theme.

### Updating

Nothing by hand: update and deploy as usual. There's no new binding, Durable Object class, migration, route, or cron, and Architect stays off until you connect a provider. [Updating to 2.0.0](https://leavethepack.dev/docs/updating-to-2/) says what changes by itself, what your repositories get, and how to go back to 1.5.3.

- **Accept the GitHub App's new permissions** when you want what they're for: Checks (a plan's check on its pull request), Variables (freezing production sets `DEPLOYS_PAUSED`), and Issues with its event (routines on new issues). Workflows, Administration, and Environments are optional too: they let the board's change bring the apply workflow, make GitHub environments for you, and check a write token's name. The board works without each, and says what's waiting.
- **To apply in a repository**, give it a GitHub environment per environment, limited to the default branch, holding that environment's write token; the repository variable `BREAKAWAY_URL`; and the apply workflow, from `npx breakaway infra init` or the board's change. [Get started with Architect](https://leavethepack.dev/docs/get-started-with-architect/) walks through it.
- Run `npx breakaway repos init <slug> --update` in each repository and merge the result, so its agents get the new core, `tasks` skill, and CLI.
- If you ran `infra init` on a 2.0.0 pre-release, run `npx breakaway infra init --update` there and merge the result.
