# Release notes

A stable release's own words. When the owner runs the **Release** workflow's stable job, a file here named for the version (`v1.4.0.md`) goes at the top of the release's notes, under its heading and above the list of merged pull requests the workflow writes. A version without one gets the list alone.

Write it before the stable, in the pull request that prepares it: what people will notice, grouped by feature, in the brand's voice ([`brand/README.md`](../../brand/README.md)), and an **Updating** section that says what an install has to do, or that it has nothing to do by hand. No work IDs: the list below it has them.
